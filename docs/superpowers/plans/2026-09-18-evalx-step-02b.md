# EVALX Step 02B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the PostgreSQL, async SQLAlchemy, Alembic, Docker, health-readiness, and isolated-test foundation for EVALX.

**Architecture:** One typed SQLAlchemy metadata base is imported by the Alembic async environment. Application runtime takes its session dependency from `DATABASE_URL`; test fixtures require an independent `TEST_DATABASE_URL` and use Alembic to create and reset only that schema.

**Tech Stack:** Python 3.14, FastAPI, SQLAlchemy 2.x async, psycopg 3, PostgreSQL with pgvector, Alembic, pytest, httpx, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-18-evalx-step-02b-design.md`

## Global Constraints

- Preserve `GET /` and `GET /api/v1/health` exactly.
- Do not implement business APIs, authentication, Redis, LLM calls, evaluation execution, or frontend work.
- Alembic is the only schema-management path.
- Database integration tests require `TEST_DATABASE_URL`; they never fall back to `DATABASE_URL`.
- Do not add a dependency unless required by a concrete implementation need.
